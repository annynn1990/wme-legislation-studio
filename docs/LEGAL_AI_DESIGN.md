# 法律 AI 分析設計原則

1. 法律資料以「法規 → 版本 → 條文」儲存；每條均可回查原文及版本。
2. 現行、歷史、草案、廢止及待確認狀態分開管理；未知效力不得自動視為現行。
3. 分析類型包括衝突、重複、漏洞、歧義、權限不明、程序缺漏及過時風險。
4. 每條草案應附立法理由、法律效果、來源條文 ID 及待決政策問題。
5. 模型來源 ID 必須經本次檢索結果白名單核驗；不可使用模型自行發明的來源。
6. 檢索式分析不等於全庫完整審計；未檢索到的法律不可假定不存在。
7. 「最佳」須依明示立法目的評估，不可以單一分數取代政策選擇。

評估面向：憲制一致、權限清晰、程序完整、法律明確、可執行、權利影響、修法成本及來源可追溯性。
